## Application public API (module `refund_desk`)
```
RefundCase(case_id: str, tenant_id: str, customer_account: str, amount: float, reason: str, currency: str = "USD", authority: "valid" | "revoked" = "valid")
DeskConfig(stack_root: Path, state_dir: Path)
process_refund(case: RefundCase, config: DeskConfig) -> DeskResult        # F1 dispose_refund
reconcile_case(case: RefundCase, config: DeskConfig) -> DeskResult        # F1 reconcile_refund; never dispatches
present(f1_result: DispositionResult, case_id: str) -> DeskResult        # pure presentation of any F1 result
DeskResult.to_dict() -> JSON-serializable dict
```
CLI: `python -m refund_desk process|reconcile --case-id ID --tenant T --customer-account A --amount N [--currency USD] --reason R [--authority valid|revoked] --state-dir DIR [--stack-root DIR | env REFUND_DESK_STACK_ROOT]`. Prints exactly one JSON object (the `to_dict()` result) to stdout. Exit code: 0 outcome `executed`; 2 `held`/`refused`/`denied`; 3 `uncertain`; 1 `failed` or usage error.
The authority fixtures (`refund_desk/fixtures/authority_valid.json`, `authority_revoked.json`, `authority_facts.json`) are shipped inside the package; `authority="revoked"` selects the revoked lineage. The evaluation time is read from the facts fixture (`evaluation.observed_at`, synthetic clock), not from the wall clock.

`to_dict()` keys (all present on every result): `app_contract` (`"refund-desk/0.1.0-dev"`), `f1_contract_version`, `case_id`, `outcome` (`executed|held|refused|denied|uncertain|failed`), `message`, `control_plane{result,reasons}`, `native{disposition,runtime_status,runtime_invoked,runtime_invocations,acknowledged,newly_executed,observed_state,error}`, `execution_claim{supported,basis}`, `effect{effect_id}`, `evidence{replay_state,replay{path,sha256,status,resolvable}|null,source[{kind,path,sha256,resolvable}]}`, `refusal{code,reasons,explanation}|null`, `permitted_next_actions` (list), `retry_permission`, `effect_absence_established`, `labels{...F1 labels verbatim...}`, `limitations` (F1 `not_verified` verbatim plus application notes), `cleanup{ok,errors}`.
Rules: `outcome` maps from the F1 disposition one-to-one (`executed->executed, held->held, refused->refused, denied->denied, unknown->uncertain, failed->failed`). `execution_claim.supported` is true only if F1 disposition is `executed` AND native observed_state is `applied` AND native runtime_status is one of `executed|reconciled|observed`; its `basis` names that status. Everything else is false. `evidence.*.resolvable` is true only if the referenced file exists and its sha256 equals the reference. `permitted_next_actions` is `[]` for executed/held/refused/denied/failed and exactly `["reconcile"]` for uncertain. `retry_permission` is `"not_established"` always. The application never changes, upgrades or downgrades a native outcome and never retries.
