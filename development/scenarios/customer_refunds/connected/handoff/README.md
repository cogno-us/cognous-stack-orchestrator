## Connected interfaces exercised

1. The Action Manifest example is parsed through
   `AgentActionManifest.model_validate`; the Control Plane fixture is forced to
   consume that canonical model projection.
2. The actual tenant-aware Control Plane
   `BoundedAuthorizationWorkflow.decide` produces the persisted decision.
3. For an authorized **synthetic** fixture only,
   `AtomicLocalControlPlaneExecutor.provision_claim` calls the Control Plane
   `provision_local_execution_claim` handoff while provisioning the actual
   Runtime `AtomicAuthorityEffectDestination`.
4. Runtime execution uses
   `AtomicLocalControlPlaneExecutor.execute` and the claim/effect transaction
   in `AtomicAuthorityEffectDestination`.

The fixture resolver is never described as institutional authentication. The
qualification wrapper requires an explicit test-owned `authenticated=True`
flag before invoking the decision handler.

## Fail-closed baseline

With the institutional grant removed, the actual Control Plane returns
`hold` with `issued_grant_missing`. The connected claim handoff rejects the
HOLD decision, and the actual Runtime observes the Control Plane-generated
effect identifier as absent. No claim, attempt, credential, processor call, or
destination effect is created.

## Boundary cases

The scoped tests additionally verify:

- unauthenticated owner resolver refusal before a Control Plane decision;
- tenant, amount, and payload substitution refusal against the connected claim;
- approval withdrawal after handoff;
- policy-version change after handoff;
- duplicate suppression after one local synthetic effect;
- local process cancellation after the Runtime transaction begins but before
  commit, leaving no durable attempt/effect and no retry authorization;
- correlation of Control Plane decision/effect IDs through claim, envelope, and
  Runtime result; claim IDs are generated by the Control Plane and execution
  attempt IDs are generated by the Runtime rather than supplied by the test.

## Reproduction

The test requires isolated checkouts at the exact pins above and these
environment variables:

```bash
export COGNOUS_ACTION_MANIFEST_SRC=/path/to/action-manifest
export COGNOUS_CONTROL_PLANE_SRC=/path/to/control-plane
export COGNOUS_EXECUTION_RUNTIME_ROOT=/path/to/execution-runtime
python -m pytest -q tests/scenarios/customer_refunds/connected/handoff/test_connected_handoff.py
```

Install the same bounded test dependencies used by O5-D
(`pytest>=8,<9`, `pydantic>=2,<3`) and the pinned Manifest/Control Plane
packages before running.

## Limitations

This is synthetic local qualification only. The grant/approval records used by
the positive boundary cases are test fixtures, not adopted institutional grants.
The destination is local SQLite synthetic refund state, not a payment processor
or settlement system. The cancellation case proves only process termination and
the tested SQLite transaction boundary; it does not prove remote processor
cancellation, fleet-wide quiescence, production identity, credential custody,
or deployment assurance.
