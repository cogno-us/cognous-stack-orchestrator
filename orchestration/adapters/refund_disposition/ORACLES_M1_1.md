## Public contract (additive; contract version string stays `refund-disposition/0.1.0-dev`; registry version `refund-profiles/0.1.0-dev`)
- `DispositionRequest.profile: str | None = None` (trailing optional). `None` or `"refund-routine-v1"` => the existing fixed behavior. `RefundProposal.case_reference: str | None = None` (trailing optional).
- Closed registry (module `profiles`, `REGISTRY: dict[str, ApprovedProfile]`, exactly two entries): `refund-routine-v1` -> action `urn:cognous:action:refund-issue-routine-v1`; `refund-high-v1` -> action `urn:cognous:action:refund-issue-high-v1`. `ApprovedProfile` (frozen dataclass): `profile_id, action_id, manifest_id, manifest_version, manifest_digest, manifest_relpath`. Nothing caller-supplied enters the registry.
- `ProfileIdentity` (frozen dataclass, exported with `PROFILE_REGISTRY_VERSION`): `profile_id, registry_version, manifest_id, manifest_version, manifest_digest, action_id, requirement_id`. `DispositionResult.profile: ProfileIdentity | None = None` (trailing optional); populated on every result that passed profile pre-flight, including holds and unknown; `None` when refused by pre-flight or request validation.
- Pre-flight (before any native Control Plane/Runtime call, `refused`, `runtime_invoked=false`): unsupported or non-string profile id -> refusal code `profile_unsupported`; `B.commitment(manifest)` != registry digest -> `profile_manifest_digest_mismatch`; native `manifest_errors(manifest)` non-empty -> `profile_manifest_invalid`; profile payload fields vs request: `refund-high-v1` requires non-empty `case_reference`, `refund-routine-v1` forbids it -> `request_invalid` with reason `case_reference_required_for_profile` / `case_reference_not_allowed_for_profile`; existing checks unchanged (tenant must equal facts tenant -> `request_invalid`).
- Everything profile-derived is read from the native manifest action at call time: adapter id (from the action's tool), requirement id, requested permissions (the action's `authority_required` scopes), payload field set, institution and authority domain, exact allowed target, max amount/unit/effects. The Runtime `LocalExecutionPolicy` is derived from the same manifest action and can only narrow (exact target URN, `max_amount = effect_limits.max_amount`, units = `{effect_limits.unit}`, institution/domain from `authority_context`, `max_effects` from the manifest); absence of a manifest limit => refuse before any native call. No hardcoded ceiling is raised.
- `reconcile_refund(request)` takes the same `profile`; a different profile finds no authorized decision (`no_authorized_decision_for_proposal`).
- For `refund-high-v1` the result `labels.not_verified` carries, in addition to the historical strings, two disclosures: that the reviewer role is a synthetic fact alias and not authenticated institutional reviewer authority, and that the manifest's evidence obligations are not evaluated natively (requirement evidence is empty) and are not verified supporting evidence. `refund-routine-v1`/default results carry the historical strings only (byte-identical).
- Unchanged: dispositions, `prior_uncertain_dispatch`, UNKNOWN mapping, no automatic retry, workspace cleanup, the private test-only fault hook, no `dev_fault`, `authenticated=false`, `producer_reported`, `nonproduction`, `retry_permission=not_established`.
